## 3. Unknown-Route & 404 Status Behavior

### Vercel Routing Analysis:
- `vercel.json` defines a blanket rewrite:
  ```json
  "rewrites": [ { "source": "/(.*)", "destination": "/index.html" } ]
  ```
- **Valid Routes (`/work`, `/about`, etc.):** Vercel returns `dist/index.html` with **HTTP 200 OK**. React mounts and renders the target page.
- **Trailing-Slash Routes (`/work/`):** Vercel obeys `"trailingSlash": false` and issues an **HTTP 308 permanent redirect** to the clean URL `/work`.
- **Unknown Routes (`/nonexistent`):** Vercel rewrites the request and returns `dist/index.html` with **HTTP 200 OK** (Soft-404). React Router catches the path with `<Route path="*" element={<NotFound />} />`, rendering the 404 UI and dynamically injecting `<meta name="robots" content="noindex, follow" />`.
- **Genuine HTTP 404 vs. Soft-404:**
  - The site **does NOT return an RFC-compliant HTTP 404 status code**.
  - Googlebot and JavaScript-capable crawlers process the `<meta name="robots" content="noindex" />` tag and exclude the page from search indexing.
  - Non-JS scrapers receive HTTP 200 with the fallback SPA shell.
  - Achieving a true HTTP 404 status requires future Edge Middleware or a Serverless Function, and is recorded as a non-blocking deployment condition.
